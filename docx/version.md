# 流萤 Firefly · 历史版本说明

## v1.0.3 · 2026-10-18

- 修复财务总览预算字段映射，正确展示实际支出、使用率、类别和预警状态；总览按当前月读取预算，不再依赖旧报告快照。
- 修正报告图片中的预算百分比倍率；未设置预算单独标识，总预算也能展示。
- AI 总结先生成再渲染，纯文字 / 纯图片 / 图文都可包含 AI 解读，关闭规则摘要不再阻断 AI。
- 图片失败时保留文字降级；报告产物使用独立文件名，前端区分 AI 生成和实际投递，并显示部分失败原因。
- 支持 config.yaml 的 llm.api_key，环境变量优先；兼容历史误填到 api_key_env 的字面密钥，展示和日志均脱敏。
- 新增 `ai 问题`（不区分大小写，支持空格 / 中英文冒号）只读 function calling，网页与 QQ 共用。该入口不执行待确认记账，也不提供写库工具。
- function_call 工具固定身份、校验参数，最多四轮工具交互、八次调用，最后一轮仅生成答案。支持 Python 3.10–3.12。
- 上传图片用于侧栏、登录、页脚、favicon 与独立报告 Logo；README 精简为使用入口，版本更新集中到本文。
- 明确列出 socksio 依赖，并补充启动时的实际导入检查。
- QQ 的 AI 查询与分析回复改为 Markdown 图片，支持标题、强调、列表、表格、引用和代码块；带流萤 Logo 与版本页脚，长回复自动分页。
- 图片通过 base64 返回原私聊 / 群聊会话，不依赖 NapCat 访问本机文件。渲染或部分发送失败时补发完整文字；临时图片自动清理。
- Markdown 禁用原始 HTML 与远程图片；补充 markdown-it-py 依赖和启动导入检查。离线提示与记账确认卡片仍以文字显示。
- 修复报告底层发送器再次过滤文字的问题，显式启用的 AI 总结和图片失败后的文字降级均能通过发送出口。
- 修复预算不会主动通知：显式启动 / 关闭调度器，启动后检查一次，此后每 60 秒检查已保存流水；支持总预算、分类预算及日 / 周 / 月 / 季 / 年周期，遵循各级提醒开关与配置时区。
- 预警发送成功后用 JSON 文本持久化等级，同一天同一预算不重复提醒，达到超支等级仍可升级通知；失败不标记、下轮重试。成功投递记录操作日志，修复提醒百分比重复放大与文本前缀误去重。

真实模型联调：首次密钥认证失败后，用户补充有效密钥，已重新通过只读 function calling、拒绝后的 AI 重解析（金额 / 发票核对）与报告 AI 总结。测试使用临时账本，不写入生产流水、不发送真实 QQ 消息。含 16 项预算预警验证在内的 80 项回归通过，原有接口套件 97 项通过、1 项模型用例跳过；QQ 图片模板已浏览器检查，实际后端截图和 QQ 收图仍需运行环境验收。

### 从 v1.0.2 更新

1. 拉取 main 后使用 `start.cmd` / `start.sh` 启动，补齐 `socksio`、`markdown-it-py` 等依赖；手动环境执行 `python -m pip install -r requirements.txt`。
2. 保留本机 `.env`、`config.yaml` 与数据库，不需清库。LLM 密钥只留在本机；`api_key_env` 填环境变量名，YAML 密钥应填在 `llm.api_key`。
3. 重启 Firefly 并刷新网页。QQ 图片回复依赖可用的 Chromium / htmlrender；手动环境可执行 `python -m playwright install chromium`，失败时系统尝试补发文字。
4. 预算通知需启用预算、单条预算提醒、阈值提醒及协议推送，并配置目标；启动后检查一次，后续每分钟检查。已有超支也会进入检查，无需重录流水。

完整配置、启动与开发参考见 [guide.md](./guide.md)，消息出口与预算预警约定见 [api.md](./api.md) 第 8 节，验收范围见 [debug.md](./debug.md)。

## v1.0.2 · 2026-10-17

- **自然语言记账修复**：识别结果按类别名和收支匹配类别，确认卡片可选择是否开票；用户选择的类别、账本和发票状态完整保存。
- **AI 读取真实数据分析**：通过服务端白名单函数读取当前用户的收支、类别、最近十笔流水、预算与账本余额，再由模型分析。模型没有 SQL、写库、配置或其他用户数据权限；模型故障时仍返回真实计算结果。
- **QQ 确认后记账**：首轮只用离线规则解析并预览，回复「接受」才保存；回复「不接受 + 修改意见」后 AI 返回结构化结果，再次确认，可反复修正；「取消」放弃。`/记` 同样需要确认。
- **流水管理**：侧栏新增独立页面，支持全部流水分页、日期 / 关键词 / 收支 / 类别 / 账本筛选，以及新增、编辑、删除。操作日志可查看修改前后快照，删除后日志保留。

### QQ 查询与数据权限

私聊可以直接问「本月花了多少」「分析本月财务」「我的净资产是多少」。含数字的查询（例如「列出最近 10 笔」）不会被当成记账。
`.env` 中 `SUPERUSERS` 指定的 QQ 号，以及 `push.target_type: private` 下的 `push.target_id`，在私聊使用网页的本地账本。
其他用户使用各自隔离账本；群聊即便由管理员发送，也使用群与发送者隔离的账本，防止在群里泄露网页财务数据。
待确认记录绑定机器人、会话与发送者，15 分钟有效，存入数据库以跨重启保留；重复或并发接受只记一次。
AI 不可用或输出无效时不会回用已被拒绝的结果，请补充修改意见重试或取消。

```bash
python -m unittest tests.test_v102 -v # 确认记账、数据权限、AI 分析与流水审计
```

首次启动 v1.0.2 会自动创建 `ff_bot_draft` 待确认表，无需清库。更新后请重启后端并刷新网页。

### Excel 使用流程

1. 在「账本管理」创建资金账户，到「Excel 导入」下载通用模板。
2. 在「记账数据」从第二行填写真实流水，保留首行表头。必填交易日期、收支类型、金额。
3. 日期可填 `2026-10-17 12:30`；收支填「收入 / 支出」；金额为正数、最多两位小数、单笔不超过 1 亿元。
4. 类别和账本使用现有准确名称；账本留空时使用上传页选择的默认账本。发票填「是 / 否」，留空视为否。
5. 上传未加密、无宏的 `.xlsx`，不超过 8MB / 2000 条。「检查文件」只预览，「导入并通知协议端」才入账。

有填写错误时整批不入账并返回行号；重复记录跳过。提交成功后按 `push` 配置发送汇总；通知失败会单独说明，账目仍已保存，请勿因此重复提交。
模板不预填示例流水，「填写说明」页不会入账。暂不支持 `.xls`、公式、合并单元格和扫描件。

### 一键更新

通过 `git clone https://github.com/ikun441/firefly_bot.git` 安装，在服务所在电脑打开设置页即可更新。
仅支持官方 `origin`、本地 `main` 分支和快进合并；未提交源码、暂存区改动或分支分叉会阻止更新。
`config.yaml` 的本地设置先备份至 `data/updates/`，再合并保留；版本号随新代码更新。`.env` 和数据库不参与 Git 更新。
更新后重启服务；依赖变化时请用 `start.cmd` / `start.sh` 启动以补齐依赖。ZIP 下载版无法一键拉取，Windows 需安装 Git。

## 2. 功能模块明细

### 2.1 记账与数据采集（P0 · 核心闭环）

- **手动记账**：类别（支持二级分类）、金额、方向、备注、对手方、发票标记。
- **自然语言记账**：LLM 抽取「昨天打车 38，请客户吃饭 260」为两笔结构化流水；
  未配置 `LLM_API_KEY` 时自动降级为规则引擎（正则 + 关键词），**服务不启动失败**。
- **两步式确认**：先抽取、给用户核对、再入库，避免 AI 幻觉直接污染账本；
  群聊场景可开 `auto_create` 直接入库。
- **批量导入**：微信/支付宝 CSV 账单（自动跳过说明行、`不计收支`、修复千分位逗号）；
  账单截图 OCR 识别；粘贴文本直接解析。均支持 `dry_run` 预览。
- **周期订阅**：房租、宽带等按周期自动入账（默认每月 1 日 08:00）。
- **资金账户（账本）**：现金/银行卡/微信/支付宝/信用卡等，带期初余额与「计入净资产」标记。

### 2.2 分析与报告（P0 · 核心闭环）

- **自定义周期**：日/周/月/季/年，或 7/14/30/60/90/180/365 天任意周期；
  也可直接指定起止日期；环比自动对比上一周期。
- **整体状况**：收支三值、净资产、账户余额、储蓄率、日均支出、支出 TOP、主要对手方。
- **支出/收入结构**：分类占比、趋势（日趋势 + 近 6 期月度趋势）。
- **归因瀑布图**：把「本期比上期多花了多少」拆解到每个类别的贡献。
- **异常检测**：同类别历史金额 z-score（阈值 2.5）+ 个人消费混入关键词识别；
  **命中即给出命中的关键词**，可解释而非黑盒。
- **预算执行**：分类预算 + 总预算，预警（80%）/超支（100%）着色。

### 2.3 税务自检（P0 · 8 项可解释检查）

| 检查项 | 说明 |
| --- | --- |
| 增值税临界点 | 月销售额距起征点（默认 10 万）还有多远 |
| 税负率偏离 | 实际税负率是否偏离行业区间（默认 1%~8%） |
| 个人消费混入 | 识别混入经营成本的个人消费 |
| 进销项倒挂 | 进项与销项异常倒挂 |
| 缺票支出 | 无发票支出金额统计（影响税前扣除） |
| 类别集中度 | 单一类别占比过高预警（默认 40%） |
| … | 其余检查项 |

每项返回 `level / actual_value / threshold_value / description / suggestion /
policy_basis`（政策原文依据），并附免责声明。

### 2.4 AI 能力（P1 · 智能化）

- **智能分类**：LLM 冷启动 + 用户纠正样本累积，越用越准。
- **对话式查询**：模型只做意图识别与参数抽取，查询由预置服务函数执行
  （`sum_by_category` / `list_recent` / `compare_period` 等）。
- **类别自演化**：新类别由 LLM 建议归属的税务口径，人工确认后落库。
- **规则摘要 + AI 解读分离**：推送摘要的数字由代码计算排版，AI 只解释
  「为什么」和「怎么办」—— 不让大模型复述金额，避免幻觉不可分辨。

### 2.5 推送与协议端（P0 · 核心闭环）

- **OneBot v11**：支持 NapCat / Lagrange / go-cqhttp，反向 WS 模式无需公网 IP。
- **定时推送**：`push.schedule_times` 配置，无人值守执行。
- **手动推送**：报告页选推送类型（文字/图片/两者）、AI 总结开关、温度、字数上限。
- **机器人命令**：`/记` `/报告` `/税检` `/明细` `/预算` `/帮助`；
  免命令直接 @机器人 即可记账或提问。

### 2.6 数据与运维

- **备份与还原**：全库 JSON 导出、上传还原、还原前自动安全备份；
  还原前可 `inspect` 预览备份内容；路径穿越防护（`Path(name).name` 剥目录）。
- **审计日志**：谁在什么渠道做了什么，全量可查。
- **建议采纳率**：`pending → adopted / rejected / ignored` 状态机，
  `ignored` 单独披露，论文可量化指标。
- **登录鉴权**：HttpOnly Cookie + PBKDF2 哈希 + 恒定时间比较 + 失败锁定，
  默认账号 `admin`。

## 5. 论文可量化指标（设计时预留）

| 指标 | 数据来源 | 实验设计建议 |
| --- | --- | --- |
| 自然语言抽取准确率 | `Transaction.confidence` + `raw_input` | 200 条口语化语句测试集，人工标注对比 |
| 分类准确率 | `Suggestion` vs 用户最终类别 | 对比「LLM 冷启动」与「累积纠正样本后」两组 |
| 异常检出率 / 误报率 | `Transaction.is_anomaly` | 注入已知异常样本，统计 Precision / Recall |
| **建议采纳率** ⭐ | `Suggestion.state` + `audit.get_adoption_stats()` | 对照组实验：有 AI 建议 vs 无建议 |
| 报告生成耗时 | `Report.elapsed_ms` | 统计不同数据量下的耗时曲线 |
