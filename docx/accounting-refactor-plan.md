## 1. 目标与建议决策

将现有“收一笔 / 支一笔”的记账工具升级为以**会计账套、会计科目、记账凭证、借贷分录、审核过账、账簿报表、期间结账**为核心的系统，保留网页、自然语言、QQ、Excel/CSV/OCR 和预算等入口。

建议按中国大陆小企业使用场景设计，采用复式记账与权责发生制，优先提供《小企业会计准则》模板。实际采用哪一套制度须确认主体适用性；“小微企业”“小规模纳税人”不是同一概念，会计制度与纳税人身份分别配置。

建议保留 FastAPI / NoneBot / SQLModel 与原生 HTML/CSS/JS，在现有单体内逐步替换核算核心。首期保留 SQLite 单实例部署；多人并发部署另设 PostgreSQL 适配与验证任务。本次不同时引入微服务、消息队列和前端框架迁移。

建议历史数据采用“指定启用日 + 人工核对期初余额”，历史流水独立只读保留。需要历史重建时采用另一条受控迁移路径，不能直接把所有收款变为收入、所有付款变为费用。

**核心闭环验收标准：**能正确处理投资、借款、应收应付、转账、费用与收入确认；每笔过账借贷平衡；草稿不影响正式账；已过账记录不可直接改删；账簿、报表可追溯且相互勾稽；关账阻断后续写入。

## 3. 业务边界与分期

### 3.1 第一阶段：核算核心内测

包含：账套初始化、年度/月度期间、制度模板与科目、期初余额、手工凭证、多借多贷、审核过账、全额冲销、总账/明细账/科目余额表/试算平衡、基础身份权限、审计与备份。

支持借款、投资、应收应付、预付与费用分摊等会计分录；尚未提供专门子系统的业务可手工制证。内测阶段不宣称已覆盖正式会计软件全部要求。

### 3.2 第二阶段：业务入口与财务报表

接入网页业务录入、QQ/AI 草稿、Excel/CSV/OCR、周期模板；实现客户供应商、应收应付未结项与核销、银行对账、损益结转、月结/年结、资产负债表、利润表和现金流量表。正式发布前完成历史迁移演练、权限和灾难恢复验证。

现金流量表不能用“总收款减总付款”替代。需要行级现金流项目、内部资金往来抵销、非现金业务排除及调整校验；来源不完整时不得输出已完成的正式报表。

### 3.3 后续扩展

固定资产卡片/折旧、存货数量金额与成本结转、工资社保、完整报销审批、发票验真与税务平台对接、多币种/汇兑、预算组织维度、企业会计准则完整模板及合并报表等另立需求。

首版允许手工录入折旧、库存成本、工资与税费凭证；不自动推算缺失数据。若实际业务必须依赖这些子系统，需将其前移到正式发布范围。

### 3.4 既有能力处置

- QQ 推送、报告图片渲染、AI 只读问答保留；统一查询新账套的数据并展示口径。
- 旧流水、旧报告保留为历史资料，不混入新正式报表，不改写历史快照。
- 旧分类保留为业务标签和科目建议来源，映射规则可版本化。
- 预算区分“付款预算”和“费用预算”，分别计算资金流出和已确认费用；不混用。
- 现有税检标为旧口径估算，默认不用于新账正式税额；新税务分析依据已核对的税务事实和生效规则重建。
- 演示数据使用独立演示账套/数据库，禁止进入正式账套。

## 4. 会计业务规则

### 4.1 基础对象

- **主体 / 账套**：账套对应明确会计主体、制度、本位币、会计年度、启用日期和时区。首版可每主体一个正式账套，但数据模型支持多账套。
- **资金账户**：银行卡、现金、微信等业务载体，绑定指定账套的可记账科目/辅助项。
- **会计科目**：按选定制度模板管理编码、名称、层级、类别、正常余额方向、启停状态、辅助核算要求、报表映射；只允许叶子科目记账。
- **原始单据**：描述经济事项的来源证据；银行流水、发票、报销单和合同不等同于记账凭证。
- **记账凭证**：凭证头 + 至少两条分录，承载摘要、业务日期、会计日期、期间、来源、制单/审核/过账身份及附件。
- **辅助核算**：首版支持客户、供应商、员工/往来单位、资金账户；部门/项目预留扩展。

### 4.2 金额和日期

1. 本位币首版限定 CNY。新 API 金额传十进制字符串（如 "100.25"），服务端 Decimal 校验，数据库以有界 64 位整数“分”存储。前端使用十进制字符串/整数运算，不用 JS 浮点累计账款。
2. 超过两位小数原则上拒绝；税费/分摊等计算结果按账套规则明确舍入并保存尾差分配过程。禁止悄悄调整用户输入。
3. 区分业务发生时间、会计日期、创建时间。会计日期以账套本地日历归属期间；审计时间统一 UTC。
4. 原始单据保留原币与原始文本。历史非 CNY 数据进入异常清单，首版不能默认按 1:1 转人民币。
5. 首版新核算金额统一限值并校验分录/凭证合计与聚合范围，避免整数溢出。旧 float 只作为历史读取输入。

### 4.3 凭证生命周期

正常流程：

`草稿 draft → 待审核 submitted → 已审核 approved → 已过账 posted`

- 草稿允许修改；提交后锁定内容与版本。
- 驳回或制单人撤回后回到草稿，记录原因并使旧审核记录失效。
- 已审核、未过账凭证若需更改，先由授权人员撤销审核再修改，保留轨迹。
- 过账前重新验证权限、版本、期间、科目、借贷平衡和来源用量。审核成功不保证以后永远能过账。
- 作废仅用于未过账凭证，保留对象与原因；不直接物理删除。被驳回的凭证不是作废凭证。
- 已过账永久保持 posted，不允许反记账、删除、插入序号或直接修改分录、日期、科目、金额与操作身份。
- 完整冲销是新增独立冲销凭证，经审核过账后通过关系表关联原凭证。原凭证显示“已全额冲销”，原分录依然存在。
- 首版只提供全额冲销；部分退款是独立经济事项，不能随意复用“全额冲销”按钮。

正式记账采用不可逆方案，依据《会计软件基本功能和服务规范》关于已记账凭证不可改删及编号的要求；具体交互、红字实现方式和审批分工属于本项目设计。[财政部原文，第 21 条](https://www.mof.gov.cn/jrttts/202408/P020240809318551591785.pdf)

### 4.4 平衡与过账约束

- 每条普通分录只填借方或贷方，金额大于零；至少两条分录；凭证借方合计等于贷方合计。
- 红字冲销采用同科目、同借贷方向、相反效力；技术存储采用 `amount_minor > 0`、`side = debit/credit`、`effect_sign = +1/-1`。普通凭证仅 +1，全额冲销凭证逐行复制原凭证并反转 sign。有符号借方合计必须等于有符号贷方合计。二次冲销和重复冲销默认禁止。
- 已停用科目、非叶子科目、跨账套科目、缺少必需辅助项、日期不属于可用期间，全部拒绝过账。
- 凭证号在过账事务中按“账套 + 年度 + 期间 + 凭证字”连续分配；草稿使用草稿编号。已过账序号不得复用或重排。
- 过账记录、编号、来源分配、审计记录与幂等结果在同一数据库事务提交。任何一步失败全部回滚。
- 正式报表只取已过账分录；approved、submitted、draft 都不计入。
- 新资金账户初始余额由期初账确定，不允许直接修改 initial_balance 改账。
- 来源已入账限额按有效分配累计检查，冲销释放或抵销的用量必须有对应记录；不得简单删掉来源关联来重复记账。

### 4.5 结账与更正

月结顺序：检查来源与凭证 → 处理未审核/未过账事项 → 对账 → 调整/计提 → 损益结转 → 试算与报表勾稽 → 关闭期间。

- 截至关账时，本期凭证必须完成过账或有明确作废/迁移处理；不得把仍属于本期的草稿静默排除。
- 必需辅助项缺失、期初未核定、未平衡、对账差异未解释、待迁移异常未解决均应阻止正式关账。
- 银行未达账项允许经确认后保留，但需形成可追溯余额调节表，不能为“对平”而虚造凭证。
- 损益结转凭证单独标记；利润表按结转前本期发生额计算，避免结转后收入费用显示为零。年末本年利润与利润分配结转按选定制度处理。
- 关账与过账竞争使用同一账套/期间锁定策略：关账先冻结新增写入，再检查并提交关闭；不能出现“检查完成后又插入一笔”。
- 首版不提供反结账。已关账期间不得补写，发现错误依据适用制度及错误性质，在开放期间办理更正并关联原记录；跨年度重大事项需明确会计处理后制证，不能一概计入当期损益。
- 未关账报表标注“未结账”，已关账报表保存数据版本、模板版本、生成时间和勾稽结果。

## 5. 典型业务与分录验收样例

下表金额均为人民币；除明确标注外，假设不涉及需要单独核算的税额，仅用于解释会计行为。正式科目编码与名称以确认的制度模板为准。

| 事项 | 借方 | 贷方 | 必须体现的区别 |
| --- | --- | --- | --- |
| 股东投入 100,000 | 银行存款 100,000 | 实收资本 100,000 | 资金增加，营业收入不增加 |
| 银行借款到账 50,000 | 银行存款 50,000 | 短期借款 50,000 | 资产与负债同时增加 |
| 偿还本金 10,000、利息 100 | 短期借款 10,000；财务费用 100 | 银行存款 10,100 | 只有利息影响当期损益 |
| 现金存银行 2,000 | 银行存款 2,000 | 库存现金 2,000 | 不增加收入费用；内部资金流动抵销 |
| 业务已完成，赊销服务 10,000 | 应收账款—客户 10,000 | 主营业务收入 10,000 | 收入确认不依赖收款日 |
| 后续收客户款 6,000 | 银行存款 6,000 | 应收账款—客户 6,000 | 不重复确认收入，未结 4,000 |
| 购入材料未付款 3,000 | 原材料 3,000 | 应付账款—供应商 3,000 | 采购不直接全计费用 |
| 支付前述供应商款 2,000 | 应付账款—供应商 2,000 | 银行存款 2,000 | 应付未结 1,000 |
| 预付全年房租 12,000 | 预付账款 12,000 | 银行存款 12,000 | 付款时不一次性确认为全年费用 |
| 当月确认房租 1,000 | 管理费用—租赁费 1,000 | 预付账款 1,000 | 无当月付款仍有当月费用 |
| 购入符合资本化条件设备 6,000 | 固定资产 6,000 | 银行存款 6,000 | 付款不等于费用；折旧另制证 |
| 办公费用当期支付 200 | 管理费用—办公费 200 | 银行存款 200 | 可通过业务模板生成草稿 |

含税业务须按纳税人身份、业务类别、适用税率/征收率、含税口径及凭证条件拆分价税。不得仅据 has_invoice=true 推断可抵扣或自动套用统一税率。

综合验收场景（上述税额假设下，互相独立于其余样例）：

1. 投资 100,000、借款 50,000、银行支付费用 200、赊销服务 10,000、回款 6,000。
2. 期末银行存款 155,800；应收账款 4,000；资产总计 159,800。
3. 负债 50,000；期末权益（含当期利润）109,800；收入 10,000；费用 200；净利润 9,800。
4. 经营活动现金净流量 5,800，筹资活动现金净流量 150,000；现金净增加 155,800。
5. 对费用 200 做全额红字冲销后，银行存款增加 200、费用归零，原凭证与冲销凭证均能追溯。
6. 任意未过账草稿不能改变上述正式数字；关账后所有入口不能向该期间新增过账。

## 6. 数据模型草案

所有新账务表带账套归属或通过受约束外键继承归属；跨账套引用在服务层和数据库层共同阻断。名称仅为草案，实施时统一加 ff_ 前缀。

| 表 / 对象 | 关键内容 | 核心约束 |
| --- | --- | --- |
| principal / identity_binding | 真实操作身份、网页登录、QQ bot/群/发送者绑定 | 不把 QQ 群号直接当作会计主体；身份绑定需明确授权 |
| accounting_entity / book | 主体、账套、制度及版本、CNY、启用日、时区、模式 | 制度启用后变更走专门转换流程 |
| book_membership | principal_id、book_id、角色、生效状态 | 账套成员唯一、服务端鉴权 |
| fiscal_period | 年、月、起止日、状态、关闭人和时间、版本 | 账套内期间不重叠；年度状态约束 |
| chart_account | 编码、层级、类别、余额方向、叶子状态、辅助要求、现金属性 | 账套内编码唯一；有历史记录只能停用，不能删除 |
| cash_account | 资金账户及其科目/辅助项映射 | 每个资金账户映射明确，不重复计算 |
| auxiliary_item | 客户/供应商/员工等，类型与编号 | 账套内类型编号唯一 |
| source_document / attachment | 原始资料、来源渠道、外部编号、文件哈希、原始日期、解析状态 | 原始内容留存；附件变更追加版本；跨渠道重复检测 |
| voucher | 日期、期间、摘要、种类、状态、版本、身份、来源、正式编号 | 正式编号唯一；posted 后保护财务字段 |
| voucher_line | 科目、side、amount_minor、effect_sign、辅助项、现金流项目 | 外键有效；行号唯一；行内校验与整证平衡 |
| voucher_source_allocation | 单据/行与凭证/行的关联及金额 | 支持一单多证、多单一证，累计有效分配不超限 |
| approval_record | 审签动作、操作者、目标版本、原因、时间 | 审核绑定具体内容版本 |
| reversal_link | 原凭证、冲销凭证、原因及有效范围 | 首版一对一完整冲销，禁止重复 |
| open_item / settlement_allocation | 应收应付来源、到期日、核销对象与金额 | 部分/多次/多对多核销，累计不超未结额 |
| reconciliation / match | 银行导入行、账内行、匹配、未达解释、调节表版本 | 自动建议后人工确认，重复导入幂等 |
| opening_batch / opening_line | 期初及年中启用累计数据、审核、冻结、来源 | 只计一次，不计入本期收入/费用或现金流 |
| number_sequence / idempotency_record | 凭证号序列、请求键、载荷哈希、执行结果 | 并发唯一；同键不同载荷冲突 |
| migration_batch / migration_item | 基线、迁移方式、映射版本、旧记录 ID、金额差异、状态 | 重跑不重复导入，保留完整对照 |
| report_snapshot | 账套、期间、报表模板/账务版本、结果与勾稽 | 可重现，旧快照不可覆盖 |
| accounting_audit / outbox | 身份、动作、对象、前后版本、请求与推送事件 | 核算审计只追加；推送失败不回滚已提交账务 |

补充约定：

- 当前选用唯一 opening 类凭证作为期初事实，经审核过账核定；全零期初可显式核定。不得再存另一套重复计入的期初余额。
- 余额表 / 汇总缓存不是独立事实来源。事实为已核定期初 + 已过账分录，缓存可重建并核对。
- 资产、负债、权益等分类与正常余额方向分别保存；报表列示需处理借贷异常余额及重分类，不能简单按单一方向显示正数。
- 数据库约束包括外键、唯一、行级 CHECK；整张凭证借贷平衡由统一过账服务在事务内检查，不能声称普通 CHECK 就能跨行保证。
- SQLite 启用外键、配置写入等待并使用明确的写事务策略，锁定序列与期间；不得只依赖在 SQLite 不生效的 SELECT FOR UPDATE。
- 对 posted 头、分录、来源财务分配设置数据库触发器等保护，阻断应用常规写路径的 UPDATE/DELETE/追加分录。数据库管理员特权不由业务软件绝对防护，辅以只追加审计、备份与完整性校验。

API 契约：

- 金额字符串和稳定枚举；凭证 PATCH / 动作携带 expected_version。版本不匹配返回 409，禁止覆盖他人已审核内容。
- 创建、导入确认、过账、冲销草稿、核销、周期生成、迁移执行等写操作携带 Idempotency-Key；存储键、动作、账套、载荷哈希及结果。
- 同键同载荷返回原结果；同键不同载荷返回 409。并发重复请求最多提交一次。
- 统一明确 401/403/404/409/422 等 HTTP 状态及机器错误码，如 BOOK_FORBIDDEN、PERIOD_CLOSED、VOUCHER_UNBALANCED、SOURCE_OVER_ALLOCATED。
- 保留 success/data 风格可降低前端改动，但新接口不继续用 HTTP 200 包裹所有错误。
- 分页、日期边界、账套时区与报表版本写入 API 文档。

旧 /api/transactions 的读取在过渡期标注 legacy_cashflow。新账套启用后，旧写接口不得绕过新核算核心：网页/QQ/导入客户端更新为 v2，旧写请求返回明确的升级提示；不把“创建已确认流水成功”静默解释成“会计过账成功”。历史账套冻结写入，不实行旧流水与正式凭证两套独立写账。

## 11. 历史数据迁移与回退

### 11.1 预检

迁移前生成只读盘点：各用户、资金账户、分类、币种、流水数量、起止日期、金额合计、未确认/疑似重复、空账户/空分类、孤立引用、已存余额、历史报告和备份版本。保存源码版本、数据库副本与附件校验清单。

float 转换规则：使用可解释的十进制表示转 Decimal，再按两位小数规则转分；保留原值、转换结果及差额。超精度、极值、非有限数、不支持币种和异常引用均进入异常清单。不得以四舍五入后的“平衡”掩盖数据问题。

### 11.2 路径 A：按启用日期建新账（推荐）

1. 选择启用日期 D，明确旧系统最后可记日期为 D 前一天，选择主体、制度和资金账户映射。
2. 旧系统资料归档只读，新账从 D 开始。迁移前备份并冻结所有旧写入入口，包括机器人、订阅、导入和外部 API。
3. 导入截至 D 前一日经核对的全部科目余额、辅助往来未结项、银行未达项、固定资产等必要期初明细。
4. 旧系统资金余额作为核对参考，不能代替完整期初：还需补充借款、应收、应付、资产和权益等。
5. 年中启用需补充年初余额、年初至启用日前累计发生额、当年利润及现金流累计数据，明确它们的查询来源，防止与期初余额重复累加。
6. 无法解释的差额列为待处理；禁止默认计入实收资本、收入或任意“平衡科目”。期初未审核核定时只允许演练，不能宣称完成正式启用。
7. 期初借贷平衡、银行与往来核对、报表勾稽通过后，由指定人员确认冻结，开放新账写入。
8. D 前的历史流水不再迁移为影响余额的凭证；查询时明确区分旧流水与新账。

优点：不会伪造过去的会计事实，核对范围可控。限制：缺乏累计资料时不能自动生成完整的当年全年报表，页面须限制或标明覆盖区间。

### 11.3 路径 B：重建历史会计账（可选）

- 选定历史起点与起点前期初余额，之后逐笔/按有依据的规则重建经济事项。此路径不能再叠加路径 A 在 D 的全部期初余额。
- 建立旧分类 → 科目建议、资金账户 → 科目、交易 → 来源单据的映射，保留旧 ID。
- 配对识别内部转账、借款与还款、回款与收入确认等，仅凭旧分类不自动决定会计科目。
- 缺少资金账户、会计主体、税务口径或原始凭据的记录进入待补充队列；高置信度也只生成草稿。
- 重建应收应付、预付款和固定资产需要外部资料，不能由收支反推全部余额。
- 人工复核后分批过账，按账户、科目、期间和辅助项核对。正式历史报表只有在覆盖完整且审核通过后才能生成。
- 预算、类别标签与周期模板单独迁移，周期模板在验证前不自动运行。
- 两条路径是可选方案，不能对同一期间双重入账。

### 11.4 切换、核对与回退

- 先使用备份副本完整试跑，记录耗时、异常数量、差额与人工处理项；迁移批次采用旧记录 ID + 目标账套 + 策略版本的唯一约束，重复执行不重复制证。
- 正式切换使用维护窗口，冻结所有写入及调度，不采用两套账并行独立双写；保留只读对比与核对报表。
- 核对项：记录对照完整、转换金额差异可解释、借贷平衡、资金与银行核对、往来合计与总账一致、资产负债表平衡、利润勾稽、现金流与资金变动一致、权限隔离。
- 新系统尚无真实新写入时，失败可停止新服务，恢复旧数据库/程序及调度配置，使用切换前快照恢复服务。
- 新系统已有真实写入后，不能简单降级旧程序或删除新表。先冻结新写入、导出新增资料并核对，再选择修复继续运行，或经确认的人工承接方案；不能丢失切换后的凭证。
- 旧备份 v1 只还原到隔离旧库，再通过迁移工具导入；禁止直接覆盖 v2 正式账库。
- 升级器需检查结构版本、维护状态、迁移结果和备份可恢复性；大版本不能继续仅靠源码快进与重启完成。

## 12. 验证与验收方案

| 编号 | 验证内容 | 通过标准 |
| --- | --- | --- |
| A01 | 精度与金额边界 | 0.10 + 0.20 精确等于 0.30；超精度、NaN、无限值和越界拒绝 |
| A02 | 多借多贷与红字 | 普通/冲销凭证分别平衡；空凭证、零金额、借贷差一分全部拒绝过账 |
| A03 | 状态机与不可变 | 非法状态转换拒绝；posted 直接改删/追加分录在业务与数据库层受阻 |
| A04 | 草稿隔离 | 保存/修改/审核草稿不影响正式余额和报表 |
| A05 | 并发与幂等 | 两个连接同时过账只成功一次；同键不同载荷冲突；序号不重复 |
| A06 | 期间锁 | 关账与过账竞争时只产生合法结果；所有入口拒绝向已关闭期间过账 |
| A07 | 综合账务 | 第 5 节综合场景余额、利润、权益、现金流精确匹配 |
| A08 | 权责发生制 | 赊销确认收入、回款不重复计收入；预付付款与费用分摊分离 |
| A09 | 冲销及追溯 | 原凭证不变，新增冲销影响正确；重复冲销拒绝；关联可追溯 |
| A10 | 身份与归属 | 跨账套查询/写入拒绝；不可伪造审核身份；QQ 用户/群映射不串账 |
| A11 | 导入与周期模板 | 重复确认与调度重试不重复；坏行预览可定位；失败批次按约定原子回滚 |
| A12 | 来源和核销 | 多单多证、部分收付款累计不超额；已有收入的银行回款只核销不重复确认 |
| A13 | 账簿报表勾稽 | 总账=明细汇总；试算平衡；资产=负债+权益；利润与权益变动衔接 |
| A14 | 现金流量 | 内部转账排除；借款列筹资；购置资产列投资；非现金分录不进入现金流 |
| A15 | 结转与年界 | 结转后利润表不归零；跨年承接、年中启用累计口径不重复 |
| A16 | 银行对账 | 部分/多笔匹配与未达项可解释；调节后余额一致，不自动虚造记账 |
| A17 | 迁移 | A/B 各自独立演练；旧记录逐项对照；异常不吞掉，重跑幂等 |
| A18 | 备份恢复 | 新表/附件/审签/映射完整恢复；结构不兼容拒绝覆盖 |
| A19 | Web / QQ / AI | 网页全链路通过；QQ 接受只创建草稿；AI 白名单只读、无越权 |
| A20 | 现有回归 | 有价值的登录、隔离、导入、推送降级等保留；旧流水语义测试明确迁移 |
| A21 | 事务故障 | 在编号/分录/来源/审计写入间注入失败，不出现半笔凭证；通知失败不重复记账 |
| A22 | 凭证来源与附件 | 原始文件可校验，重复发票不能换渠道二次入账；过账引用不可被覆盖 |

测试层次：独立领域规则测试、临时数据库集成测试、隔离 API 测试、网页端到端测试；不连接真实 QQ，不调用计费模型，不写用户正式配置或数据库。现有 unittest 与 tests.run_isolated_api 可作为回归起点，无需为重构更换整套测试框架。

性能先收集实际数据量。暂定候选验收集为 10 万凭证 / 30 万分录，明确硬件、索引与并发条件后测分页、过账及报表耗时；性能数值需确认后写入验收，不在未测试时承诺吞吐。

| M3 入口与业务 | 网页、导入、QQ/AI 草稿、周期模板、来源、往来核销 | 所有写入口统一，来源不重复，业务链路可演示 |
| M4 期末与报表 | 对账、调整、损益结转、月结/年结、三表及导出 | A13—A16 通过；凭证到账表及原始资料可追溯 |

排期在 M0 根据实际数据量、使用人数、会计资料完整度和扩展模块范围估算。不能只按“换几张表”的工作量承诺完成日期。

正式发布前需另建“规范条款—功能—验证证据”对照清单。核心内测与可用于正式企业账的发布是两个门槛；第 3.3 节暂缓的能力，若属于实际适用规范的必需项，必须补齐后再宣称完整适用。

| 编号 | 待确认问题 | 建议 | 对范围的影响 |
| --- | --- | --- | --- |
| C01 | 主要用户与使用目的 | 小企业正式会计核算；若只是个人复式账应缩小范围 | 决定科目、报表、权限及规范要求 |

| C04 | 纳税人与税务范围 | 与会计制度独立配置；先支持事实记录与手工税费制证 | 自动税额、验真、申报增加外部集成和规则维护 |
| C05 | 使用人数与审核 | 正式企业账默认制单与审核分离；单人仅选明确的个人/内测模式 | 决定身份系统、角色及审签配置 |
| C06 | 历史处理 | 路径 A：启用日 + 已核定期初；旧流水只读 | 路径 B 需要补充历史依据与更多人工复核 |
| C07 | 启用日与期初资料 | 选择一个月初，准备资产负债、往来及年内累计资料 | 决定可生成报表的起止范围 |
| C08 | 首次交付范围 | 先核算核心内测，再完成入口、三表、对账与迁移正式版 | 决定验收与分批发布计划 |
| C09 | 数据库与部署 | SQLite 单实例先行，明确写并发控制；多人部署评估 PostgreSQL | 数据库切换会新增驱动、迁移、备份与锁验证 |
| C10 | 前端方案 | 延续原生页面模块，新增会计交互 | 框架重写不与本轮核算改造捆绑 |
| C11 | QQ 与自动化权限 | QQ 录入草稿和查询，网页审核过账；周期只生成草稿 | 如需自动审核，另设可查询可追溯的确定规则与授权 |
| C12 | 更正策略 | 已过账不可逆，首版完整冲销；不提供反结账 | 明确改错工作流与用户培训 |
| C13 | 预算口径 | 分开设置付款预算与费用预算 | 防止历史预算数值直接套入新账 |
| C14 | 正式使用与验收责任 | 指定项目确认人及会计口径复核人 | 科目、期初、税务和迁移核对需要明确签收 |
